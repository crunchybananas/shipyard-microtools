# Wildhaven independent release review — 7 October 2026

The local candidate passes the applicable code and packaging gates after this independent review. Final source is **`1f50826ddb37465c6199a56f30b7247219fe4457`** on `codex/wildhaven-clearer-living-towns`, in the isolated `wildhaven-implementation` checkout. No push, PR, merge or deployment has occurred. This is a reviewable local-game release candidate; it is not proof of perfect physical-iPad behavior or real network multiplayer.

Two independent reviewers inspected save/companion behavior and interaction/research/rendering behavior. The root agent checked repository gates, runtime packaging and remote drift, fixed the findings, and ran one browser at a time with disposable storage. Existing earned saves, art and the canonical checkout were preserved. CNC, controller, Workshop/Makera, desktop UI and moth work were untouched.

The review corrected three concrete findings: selected-well inspector refresh restored an unwanted floating label on touch; lifting the original pinch finger left stale drag coordinates; and research-map copy incorrectly implied scholars were required to start a project. Either pinch release order now rebases to the remaining finger, and scholars are correctly described as advancing research. Visual inspection also moved touch-preview reach information into the placement tray so a duplicate floating label cannot obscure the header. The boundary and home markers remain visible. Four pre-existing unused bindings were cleaned without changing simulation behavior or public exports.

**Save compatibility.** The 27 companion tests and four journal tests pass. An independent additional check retained earned v2 journals of 10, 32 and 13 entries through three reloads; the Day 5 v4 save remained identical. V1 history survives migration with one migration entry and stable event IDs. Journal repair filters malformed optional records and keeps the newest 60 without replaying rewards. Save version stays v4. Existing fresh browser evidence covers earned construction, saved journal history, reload, two-town transfers and blocked second-tab writes. The six mature before/after fixtures retain exact gameplay state apart from the intentional journal fields, camera and viewport; the fresh startup timing difference is still excluded from parity claims.

**What companion exchanges actually do.** Two independent named town snapshots live in one browser. One person can manage either town; only the managed town runs. Visits are paused and read-only. Proposing an offer reserves no goods. The receiving town must be managed, and the person at the device checks a confirmation and accepts. Acceptance rechecks both stocks and receiving capacity, then atomically stores both inventories and the completed offer. Failed writes move no goods; mirror recovery does not replay transfers. The original home key remains the home save. This is shared-device turn-taking, with no identity authentication, remote synchronization, accounts, invitations, cross-device play or human-town conflict. NPC diplomacy and battles remain separate existing systems.

**Remaining limits and omissions.** Physical iPad Safari, keyboard entry, sustained GPU/thermal performance and a genuine two-person session remain unverified. This pass does not establish multi-hour unaided enjoyment or replay the entire late-game RTS campaign from a fresh candidate save. Web Locks or storage failure blocks all management, even before companion opt-in; corrupt/conflicting records are preserved but there is no in-app export/repair flow. Undo remains single-level. The next bounded acceptance step is a physical iPad session covering rotation, keyboard forms, partial-pinch continuation, research scrolling, save/Continue and a mature town, followed by unaided tools/path feedback. Do not describe the game as perfect on iPad before that step.
